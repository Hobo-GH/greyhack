# AutoCredential

AutoCredential is the full-name successor to AutoCred. It reads current classic credential Mission Contracts, lets the operator choose indexes or `all`, attacks the requested network and LAN target, recovers the requested account credential, finalizes retained logs, and prints an organized batch report for manual Mission Contract replies.

Current release: `3.0.1`. It preserves the complete AutoCred `2.2.0` engine and the `3.0.0` family interface while giving AutoCredential its owner-accepted asymmetric authentication-gate circuit. A real 11-contract batch completed seven jobs, returned seven credentials, continued through four targeted-access exhaustions, rotated diagnostics, and printed the final report.

## Install

Set a private `PIN` in `autocredential-3.0.1.src`, then compile it as `/bin/autocredential`. Players may choose `/bin/autocred` as a personal alias, but the official command and AutoDeploy manifest use the full name. `MAIL_USER`, `MAIL_PASSWORD`, and the optional PoisonLib source are intentionally blank in the public source.

## Operation

- Enter indexes or `all` to run selected credential contracts.
- Use `fresh` or `refresh` to replace the current MetaMail snapshot.
- Use `help` to show the front-page guide again.
- Reply manually in `Mail.exe` with each recovered password; AutoCredential does not submit mission replies.

Runtime state remains under `/root/autoscripts/credential`, and exact-version exploit knowledge is shared through `/root/vulndb`. The runtime namespace did not change with the full-name release, so existing task and diagnostic paths require no migration.
